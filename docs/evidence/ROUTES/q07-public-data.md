# Q07 公開データによる代替の確認

確認日: 2026-09-15。交通API契約なしは利用者の確定回答。基本経路はPR #68で統合済み。

ROUTES Issueと経路条件仕様に対象地域の限定はない。東京駅周辺は今回の実操作検証地点であり、交通要件を東京だけへ縮める根拠にはしない。

- [ODPTの提供概要](https://www.odpt.org/overview/)は鉄道等のREST JSONと主にバス・船のGTFS提供を案内している。[東京メトロの提供開始告知](https://www.odpt.org/2022/02/24/news20220224_1/)もある。ただし、今回利用できるfeedの取得・内容照合は未実施。運行日・有効期限・対象駅・経由線・定期券規則の充足は未確認。
- [GTFS仕様](https://gtfs.org/documentation/schedule/reference/)は駅/路線/便/時刻/運行日を扱い、運賃や駅構内経路の追加ファイルもある。規格が存在するだけでは配布feedの収録を保証しない。特に要求区間の乗継運賃、定期券の経由指定と追加運賃、屋根付きの歩行全区間の根拠は未取得。
- [GTFSデータリポジトリ](https://gtfs-data.jp/)の公開窓口を確認したが、今回の短い確認では要件全体を満たす具体feedを特定できなかった。「公開データが存在しない」という判断ではない。

必要な残作業は、対象feedの取得と利用条件/有効日確認、提供元を含む駅・路線IDの対応、日付/時刻/乗継探索、実運賃/定期券照合、道路区間への接続、取得版・根拠付き保存/再表示。既存Mapbox道路adapterの置換だけでは成立しない。新規契約の可否を再質問せず、具体feedと不足項目が確定した時点で判断を依頼する。現在はconditions未達のまま。
