# 通常入口からの初回質問と回答の再整理

対象: #12 / #139 の質問・回答。#185 全画面の合格やIssue全体の完了を示すものではない。

## 修正

「自分を知る → 今日の軌跡 → 体験を開く → 振り返る」のrecordId入口では、質問が未生成だと一覧が空になり開始操作がなかった。既存のextract APIを本人の明示操作で開始し、必要な質問が生成された場合だけ質問画面へ進む。質問不要の結果はそのまま表示し、架空の質問・回答を作らない。

元記録の版が変わりquestionTextが非表示になった保存済み回答も、現行record/answerのsourceRefで再整理できる。無効な旧質問をcontext.answersへ戻さず、サーバーが保持する回答原文を使用する。

## 実操作

- 2026-09-27、専用ローカルDB、実API :3139、実build、実Codex provider gpt-5.6-luna。架空体験のみ使用。既存日記検証DBをバックアップして独立コピーを作成した。
- 通常の開始画面から「地図をのぞく → 自分を知る → 今日の軌跡 → 18:12の体験 → 振り返る」で到達。
- recordId `diary139-live-source`、v1から明示生成。実AIが「水の音以外に、この休憩で印象に残ったことはありますか？」を生成した。
- questionId `question_548fa8d1ee7ebf45867976ead6ad599991b08a81ec6940ce`。回答「検証用の回答：ベンチの木陰が涼しく、ゆっくり休めた。」を保存し、画面内の履歴導線で回答済み状態と同一原文を確認。
- 履歴から「この回答で解釈を更新 → AIで整理する」。用途「休憩」、木陰・水の音を含む感想の実生成結果を確認し、選択した内容を保存。
- 同URLをreloadし、版更新で旧質問が「元の質問を表示できません。」になっても回答原文が残ることを確認。そこから再び実生成を開始し、用途「休憩」と回答の木陰の内容を含む感想が得られた。
- Mapboxの既存設定を使用。Map canvas/スケールは初期化されるが「地図の一部を取得できませんでした」が残るため、地図全体の成功とは扱っていない。
