# 未確定事項と解消した事項

既存DBのJSONと、追加された共通基盤の契約・追加DDLを照合した。
以下は現在残る設計事項。
型だけを埋めて、動作まで再現可能になったとは扱わない。

| ID | 残る契約 | 影響と確定条件 |
|---|---|---|
| Q01 | 人物管理・プロフィール公開範囲 | ローカルの本人開始/終了・初回登録・mode別sessionはCORE v0.3.0で具体化。人物削除と関連処理、プロフィール公開範囲はSETTINGS/COMMUNITYに残る。外部公開サービスのアカウント認証はローカル本人選択とは別 |
| Q03 | 場所の更新権限と追加属性 | 検索の提供元・順序・分類・保存可能性は解消。共通placesを誰が編集するか、外部再取得との優先順位、営業時間・入口情報の保存を決める |
| Q05 | 分析・提案の計算規則 | 集計軸の判断可能日と同日複数回答の統合、提案の適合・順位・滞在時間・有効期限。AI実行のモデル設定・依頼文・結果の保存手順は共通仕様で定義済み |
| Q06 | プロフィールアイコンと媒体上限 | アイコンアップロード・avatar_pathから表示URLへの変換。Range配信・権限判定は解消。媒体の許可MIME・50 MiB上限は本案で提案した値 |
| Q07 | 交通データ・追加案内 | walking/drivingの経路取得は定義済み。cycling/transitは501と明示。定期券に使う路線・駅検索とID照合、運賃、曲がり角の指示が残る |
| Q09 | プラグイン定義と適用範囲 | plugin_settingsにperson_idがない。共通設定の権限か本人別保存かを決める。各settingsSchema、バイク・聖地・防災の固有検索と出典契約が必要 |
| Q10 | 別都市へ体験を移す保存・操作 | レシピ、忠実案／本人向け案、選択結果の保存契約とAPIが未定義。発見カードと反応の保存は共通追加DDLで解消しAPIへ反映済み |
| Q11 | 画面別の受入と地図表示規則 | [67画面の仕様](../../03_pages/README.md)を整備済み、実装後の受入は未実行。本人・友人の地図、成長段階、用途外観、建物選択、検索一覧と地図の遷移を画面仕様で照合。共有地図の2,000件上限は共通仕様に合わせた |
