# 通信・データ形式

既存の[技術スタック](../../00_stacks/README.md)に従いHTTP・JSON・multipartを使う。
以下の命名、上限、通信方法は今回のAPI設計案。
保存する意味は既存DB仕様に従う。

## URLとデータ

ベースパスは `/api/v1`。
GETは取得、POSTは作成・計算・明示操作、PATCHは部分更新、DELETEは削除。
GETとDELETEに本文はなく、未知のqueryや本文フィールドは400または422で拒否する。
JSONの構文不正・query変換不能は400、構文を読めても型・関連・値が不正なら422とする。
queryの整数・数値・真偽値は文字列から型へ変換して検査する。

通常の入出力は `application/json`、媒体アップロードは `multipart/form-data`。
APIのフィールド名はcamelCase。JSON列はオブジェクトまたは配列で返し、0/1は真偽値へ変換する。
入出力の完全な構造は[型一覧](../schemas/models.md)と[OpenAPI](../openapi.json)を正とする。
`PluginValues`とプラグイン定義のSchema本体を除き、定義にないオブジェクト項目を受け付けない。

IDは1〜80文字の不変文字列。
全要求でX-Request-IdにUUIDを送り、同じ値を応答ヘッダーへ返す。
日時はUTC Unixミリ秒、日付は実在する `YYYY-MM-DD`、日付境界は実在するIANA `timeZone` で決める。
期間指定はfrom/toの両方を送りfrom<to。fromを含みtoを含まない。
定期券のvalidToだけは当日を含む。
座標はlongitude/latitude、保存ルートの既存JSON構造ではlng/latを維持する。
GeoJSONの配列は経度、緯度の順。距離はm、時間は秒。

必須とnullの可否を分ける。
必須かつnull可の項目では、キーを含めてnullを送る。
PATCHの省略は現在値を維持、nullはnullを許す項目を消す。
配列と内部オブジェクトは全体を置換し、既存値と結合した後の全体にDB制約を適用する。
明記した既定値以外はサーバーが推測して補わない。

## 上限の初期案

| 対象 | 制限 |
|---|---|
| 記録本文・永続AIの依頼 | 最大20,000文字。その他の本文・紹介・説明は各Schema |
| 名称・題名 | 1〜200文字 |
| 一覧 | 既定50、最大100 |
| 一括位置追加・削除 | 最大1,000点、全体成功または全体失敗 |
| 一記録の添付 | 最大100件 |
| 媒体 | 1ファイル50 MiB、JPEG/PNG/WebP/MP4動画/MPEG・MP4・WAV音声 |
| ルート地点 | 2〜10点 |
| 参照の一括照合 | 1〜100件 |

これらはDB仕様に既定がなかった箇所への提案であり、既存の承認済み制限とは扱わない。
値の詳細は各Schemaに記載する。

## 応答

| 処理 | HTTP | 本文 |
|---|---|---|
| 単体取得・更新・計算 | 200 | `{ "data": ... }` |
| 新規作成 | 201 | `{ "data": ... }`、Locationに再取得URL |
| 既存外部場所の採用 | 200 | 既存Placeをdataへ返す |
| AIの受付・再試行 | 202 | 状態取得URLと発言ID。完了の意味は持たない |
| 削除 | 204 | 本文なし |
| 一覧 | 200 | `{ "items": [], "nextCursor": null }`。共有記録はtotalCountも返す |
| 媒体実体 | 200 / 206 | 全体または単一Rangeのバイト列 |

プラグイン定義一覧は全件のitemsのみでcursorを持たない。
検索結果集合・一括処理はdata内へ結果を置く。
各操作の成功応答Schemaを優先する。

保存後はID・version・日時を返し、UIはこの値で保存済み表示へ進む。
単体資源の応答はETagに `"<version>"` を返す。
複合詳細では主資源（record/place/message）の版を用い、関連資源の一括版と解釈しない。
複合結果・一覧のキャッシュ判定には使わず、本人データと媒体は `Cache-Control: private, no-store` とする。

## ページ分割

各操作に固定の並び順とIDによる同値時の順序を記載する。
サーバーで閲覧条件と検索条件を適用してからページを切る。
cursorは本人・正規化した検索条件・並び順・最後に返したキーに束縛し、利用者が変更できない形式にする。
条件の異なるcursorは400。省略時は先頭。

更新中の一覧はスナップショットを保証しない初期案とする。
更新で並び順が変わると途中ページの重複・欠落が起こり得るため、UIはIDで重複を除き、本人の保存・共有変更後には先頭から読み直す。
共有地図は別の全件取得で最大2,000投稿。超過は413、cursor/limitは受け付けない。

共通の場所詳細はPlaceDetailのcolocated/ownRecords/sharedRecords/visitsを使う。
日別のvisits/records/checkinsは、対応する一覧APIへ同じ条件で続きを取得する。
0件はreadyと空配列。取得失敗を0件として扱わない。
