## 見つかった問題と修正

| 問題 | 修正 |
|---|---|
| `control` / `content` だけでは実装形式が決まらない | 全998要素に型・renderer・DOM要素・値の取得元を指定 |
| 写真・本文・作者・日時を一つのcontentにまとめていた | 75の複合領域を子要素へ分解。一覧のカード内部もtemplateで指定 |
| 画像の3件・人物名・写真番号を固定コンポーネントとしていた | 16の重複を吸収。item.idで繰り返す操作と表示へ変更 |
| 入力や選択を押すだけで遷移する指定があった | input/changeとsubmitを分離。選択値・checked・エラーを実DOMで更新 |
| 一覧と選択欄を別々に描画すると同じカードが重複する | itemControlsとplacementで同じ行に操作を配置。ルートには二重描画しない |
| カレンダーや地図ドラッグの操作元が独立した絵/部品になり得た | 一つのカレンダーgrid、同じMapbox操作面を参照 |
| 文字数が画像中の例示値のままだった | counterForで実入力に結び付け、入力上限と同じ規則で計算 |
| 画像の「バイクマップ」を自転車と記載していた | バイクへ訂正。表示設定の背景地図・検索・現在地・下部ナビも補完 |
| オブジェクトの独立プレビューを地図と記載していた | 本人追加の目印を3D描画するプレビューと場所写真へ分離 |

## 実装時に読む指定

[component-types.json](component-types.json) は部品の意味と描画形式、一覧の内部構造を定義する。
既存ライブラリのexport名を新しく固定するものではない。
各ページの `components.json` の `implementation` がこの指定を使う。

| 対象 | 実装形式 | 値の取得元 |
|---|---|---|
| 見出し・本文・日時・件数 | DOMのh2/p/output等 | 固定コピーまたはview-model |
| 本文入力 | textarea | formの入力値 |
| 名前・検索 | input | formの入力値 |
| 単一/複数選択 | fieldsetとradio/checkbox、select | 選択肢とvalue/checked |
| ボタン | button | 文言と対象ID・操作状態 |
| カード一覧 | ul/li内の写真・テキスト・操作 | itemsとitem.id |
| 地図 | Mapbox | 地理データ・選択場所・経路・成長表現 |
| グラフ・コンパス | SVG | 集計系列・方角・距離。固定形状にはしない |
| 写真・動画 | 独立img/video | 媒体参照。UIスクリーンショットではない |
| 相棒 | v2ペットatlasの描画 | 検査済みpackageと動作状態 |
| 独立した目印のプレビュー | Three.js等の3D描画 | 編集中の形状・色・表示サイズ |

`valueFrom` はUIが必要とする値の意味を表す。
APIの正確なfield名は各 `api.json` とOpenAPIが正本であり、view-modelへの変換を実装する。
実装済みのデータ接続が存在するという意味ではない。

## 画像の扱い

参照画像を製品のimg、CSS背景、canvas texture、SVG imageへ貼り付けない。
ファイル名の変更や、カード単位への切抜きでも同じ。
画像の上に透明ボタンや入力欄だけを重ねる実装も不可。

写真・独立した装飾イラスト・ペットatlasは画像素材として使える。
本文、見出し、数値、操作を含む画面画像は素材にしない。
レビューシートの題名、画面番号、9:41や電池表示はアプリ部品に含めない。

## 検査結果

`mise exec -- node docs/01_requirements/03_pages/verify.mjs` が通過。

不正例も確認し、実装指定の欠落、screenRaster=true、画像rendererのボタン、img要素のtextareaを拒否した。
今回の目視再照合は、タイプ診断、過去の記録/統計、経路、希望と提案、テーマとメモ、相棒、地図レイヤー/目印の7枚で行った。
他画面は既存の画像棚卸しと全コンポーネント定義を構造的に見直した。
