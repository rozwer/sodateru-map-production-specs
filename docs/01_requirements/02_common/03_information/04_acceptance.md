# 確認例

[検査データ](examples.json)に入力と期待結果を置く。schemas.jsonの検査と、本文で定めた境界条件の計算例をverify.mjsで実行する。

| ID | 確認すること | 期待 |
|---|---|---|
| INFO-01 | 空入力の検索は既定条件 | 形式を受け付ける |
| INFO-02 | 検索件数の上限 | 形式を拒否する |
| INFO-03 | 媒体準備中 | 形式を受け付ける |
| INFO-04 | 削除・共有取消の根拠 | 形式を受け付ける |
| INFO-05 | 本人は非公開記録を読める | true |
| INFO-06 | 他者は非公開記録を読めない | false |
| INFO-07 | 指定共有は友人状態と独立 | true |
| INFO-08 | 共有先解除後は読めない | false |
| INFO-09 | 訪問経由の場所・日時を使用 | {"placeId":"p1","effectiveAt":1000,"endedAt":2000,"timePrecision":"exact","visitStatus":"confirmed"} |
| INFO-10 | 検索開始ちょうどの終了は期間外 | false |

| INFO-16 | 読めない根拠の現在版を漏らさない | {"state":"unavailable","currentVersion":null} |

## DB・媒体・画面での受入

1. 訪問あり・訪問なし・日時不明・取消済み訪問の記録を用意する。場所詳細と日記が同じ実効日時・場所・原文を表示する。取消は文章を消さず訪問回数から外れる。
2. 120件以上を作り、101件目以降だけが検索条件に一致する状態で検索する。一覧・総数・地図に該当が現れる。
3. 同時刻の投稿と日時不明の投稿をページ境界へ置き、cursorを進める。同一IDの重複や同時刻の欠落がない。別条件のcursorは拒否する。
4. private・selected・publicを二人の本人で読む。共有先を解除して再取得し、本文・写真・比較の引用が外れる。友人解除と指定共有解除を別々に確認する。
5. 写真一件のファイルを失わせ、本文と別の写真は表示する。その媒体だけ再試行する。動画Rangeでも権限照合を通す。
6. 根拠を訂正して傾向を開く。旧入力の結果を外し、新しい集計ではunknownを分母へ加えない。発見のsaved→dismissedで保存一覧から外れる。

本人・dataMode・DBパス・検索条件・対象IDと版・HTTP結果・再表示結果を証拠へ記録する。
