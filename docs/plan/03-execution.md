# 3. 並列作業と接続

[入口へ戻る](../../README.md) · [次：仕様書・Issueの形式](04-spec-and-issue.md)

## 最初から4人が作業する

| 担当 | 最初の着手 | 他担当の完成を待たず進められること |
|---|---|---|
| A | UI共通基盤 | 文言・翻訳、トークン、テンプレート、地図・チャット部品と表示状態 |
| B | 本人領域と体験記録 | 起動・保存、体験・媒体・訂正のAPI、再取得・再起動の検証 |
| C | 共通の場所・経路取得と検索・案内 | 外部取得、地点と経路の処理、入力検証、API・スキーマに沿った検証 |
| D | 共通AI実行と自己理解 | AI接続・取消・失敗処理、指定入力からの分析、会話・結果保存の検証 |

スキーマ・API・入出力例は仕様作成時にIssueへ付けます。UIを見てからAPIの形を決める段取りにしません。処理側は指定スキーマの検証用DBと入力例で実装・検証できます。

Bさんが薄い共通処理を作る間も、C・Dさんは外部取得・計算・AI・機能固有の実装を進めます。共通処理は利用できる範囲を早く渡し、機能全体の完成まで抱えません。

## 共通UIが揃った後

Aさんは、起動・設定、地図、自己理解、共有・地域、拡張機能などの画面群を複数Codexへ並列に渡します。地図やチャットを各画面で作り直さず、共通部品を使います。

各Codexには、対象画面、状態一覧、画像、文言キー、使うテンプレート、API入出力、検証例を渡します。共通部品が揃っていない画面のために全画面を待たせず、利用できる部品で完成する画面から進めます。

## B〜Dさんの次の仕事

機能を完了した担当者から、次の着手可能な機能を取得します。初期配分は予約ではありません。例えばCさんが防災に時間を要している場合、未着手のバイク機能はB・Dさんへ移せます。地理処理の共通関数を使い、API・保存・検証まで一括して引き継ぎます。

各担当は、進行中の仕事に加えて、対象範囲内の「次に着手できる仕事」を一つ把握します。依存待ちになったら、未完成箇所と再開条件を残し、取得範囲が競合しない仕事へ移ります。待ち時間を埋めるために、未採用機能や不要な検査を増やしません。

UIの初回実装が終わったAさんには、実APIが届いた画面の通し確認・修正が続きます。Aさんは画面群へのCodex配分を調整し、B〜Dさんは未着手機能の担当を移すことで、負荷の偏りに対応します。

所要時間は未実測です。全員の同時完了を約束する固定時間割ではなく、待ちと負荷の偏りを見て仕事を移せる計画とします。

## 同じファイルを取り合わない

- Aさん側は `src/web/` と各機能の `ui/`、処理側は該当機能の `server/`・`migrations/` を編集します。
- 各機能のAPI・SQL・テストはその機能へ置きます。巨大な共通APIファイルや全体DDLを複数人で編集しません。
- 文言・トークン・テンプレートはAさん、共通AIはDさん、共通地理処理はCさんが最初の変更窓口になります。利用者全員が独自版を追加しません。
- 起動ファイルは機能routerを登録する薄い構成にします。個別endpointの追加は各routerで完結させます。
- 共通契約の変更が必要なら、変更理由・利用箇所・新しい入出力例を一緒に示します。提供側だけ型を変えて利用側の修正を放置しません。

担当移管は機能の境界で行います。途中のファイルを複数人で同時に直すのではなく、現在の成果・残件・通過条件を渡して担当を切り替えます。

## 接続を後回しにしない

| 確認 | 通過条件 | 主担当 |
|---|---|---|
| 共通基盤 | 利用側が呼ぶ形式で実行でき、代表正常・失敗を再現できる | 各共通基盤の担当 |
| UI | 共通の入力例を使い、全状態・操作・遷移・送信内容が仕様どおり | A |
| 処理側 | 実API・DBで保存・再取得・再起動・固有の失敗条件が仕様どおり | 機能担当 |
| 利用機能全体 | 実画面→実API→保存→再表示と、該当する失敗・復帰が成立 | Aと機能担当 |

バックエンドIssueは、UIがなくても実API・DBの受入で完了できます。UIも契約に沿ったモックで受入を進められます。ただし、片側の合格を利用機能全体の合格にはしません。

実APIが使える機能から、Aさんが画面をつないで確認します。結果はその機能の `acceptance.md` に残します。問題は該当するUI・処理側の担当へ戻し、接続専用の担当・Issue群は設けません。

モックと実APIで別のデータ形式を作らず、同じ契約と入出力例を使います。実AI・外部データが通過条件なら実接続で確認し、固定結果で代用して完成にしません。
